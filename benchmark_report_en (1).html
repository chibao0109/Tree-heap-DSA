Runtime Benchmark of Tree Structures

Binary tree, BST, AVL, Min-heap, Max-heap. Main figures come from C++ (g++ -O2), on two datasets of 5000 and 100000 elements.

Methodology

  • 5 structures × 4 functions (insert, search, delete, traverse), 20 measurements per language in total.
  • stable: random data. worst: data sorted in ascending order, which degenerates the BST into a linked list.
  • Search and delete process all n elements in a fixed shuffled order, identical across all languages.
  • Timing is measured by the code itself, repeating for about 300 ms and then averaging. The tables report the median across runs.
  • Reliability note: at 100000 worst, each language was measured only once because each run takes more than 60 seconds. Differences of tens to hundreds of times are trustworthy, but differences under 2× should not be over-interpreted.

Observations

  • BST degenerates most clearly on the worst file (sorted data): from 15 ms to over 10 seconds when n grows 20×. AVL stays almost unchanged between stable and worst.
  • AVL is slower than BST on random data because it must update heights and rotate the tree, but it never degenerates. Heaps are very fast because they only work on arrays.
  • On the worst file (ascending), min-heap hardly has to swap any elements, while max-heap must push every element up to the root, so the two heaps differ.

Observations

  • Binary tree and heap have no key ordering, so each lookup must scan in O(n). Looking up all n elements becomes O(n²): when n grows 20×, time grows about 400× (20.7 ms to 8,442 ms).
  • Heaps are about 2 to 3 times faster than the binary tree because they scan a contiguous array, while the tree has to follow pointers.
  • AVL is always stable. BST only matches AVL on random data, while on the worst file it is about 370 times slower.

Observations

  • On random data, BST is slightly faster than AVL because it does not need to rebalance. On bad data, AVL is about 250 times faster than BST at n = 100000.
  • Deleting an arbitrary value from a heap requires a sequential search, so it is also O(n) each time. This is a weakness of heaps, since a heap is only designed for fast access to the root element.

Observations

  • All 5 structures are O(n) for one traversal, so all values are very small. Heap is fastest because it only sums sequentially over an array.
  • At n = 5000, values around 0.002 ms are close to the timer resolution, so the ratios are for reference only.
  • BST on random data is clearly slower at n = 100000 (1.97 ms versus 0.23 ms on the worst file). Hypothesis: nodes of a random tree are scattered in memory, which is cache-unfriendly; not verified.

Conclusions

  1. Theoretical complexity matches the measurements. The O(n²) operations (search/delete of binary tree and heap, all BST operations on the worst file) grow about 400× when n grows 20×.
  2. AVL is the most stable choice: it never falls into the bad case that BST does, at the cost of inserts being about 1.7× slower on random data.
  3. Heap is only good for insert and traversal. If you need to search for or delete arbitrary values, heap is not suitable.
  4. Binary tree is usually only fast at insert and traverse. Since there is no key ordering, search and delete are both O(n) per element.

Observations

  • Go, Java, and C++ are in the same range: differences are mostly under 1.5×, and which language is fastest varies by measurement. Java wins most often at n = 5000 and 100000 stable, especially on heap scans (about 1.5 to 3 times faster than C++), possibly because the JIT optimizes array-scan loops; this is an unverified hypothesis.
  • JavaScript is about 1.4× slower than C++ at n = 5000, but on binary tree search/delete it is about 2 to 3 times slower than C++.
  • Python is about 30 to 45× slower than C++ at n = 5000. At n = 100000 (insert and traverse only) it is about 13× on stable and 38× on worst, largely due to BST insert on the worst file (185 seconds versus 10 seconds for C++).
  • Changing language only changes the constant (a few times to a few dozen times), while choosing the right structure changes the complexity class: BST worst on C++ (10,360 ms) is still slower than AVL on Python (900 ms) for insert.
